Introduction to FoodHub

Transforming restaurant food ordering through modern web technologies

💡

What is FoodHub?

A comprehensive, full-stack web application designed to connect diners and restaurants seamlessly. It replaces static paper menus and crowded counter queues with a dynamic digital storefront.

🎯

Core Purpose

To provide customers with effortless menu exploration, transparent pricing, and instant checkout while granting kitchen operators complete live control over dish availability and order dispatch.

⚡

How It Works

Customers browse categorized dishes, filter by dietary requirements, add items to cart, and place orders. The kitchen staff receives new tickets instantly on their management board to start cooking.

📌 Key Takeaway: FoodHub acts as a centralized operational hub that eliminates friction between customer orders and kitchen preparation.
Slide 03

Problem Statement

The critical shortcomings of traditional food ordering systems

❌ Traditional Ordering Bottlenecks

  • • Long Queues & Peak Delays: High customer wait times during lunch and dinner rushes lead to lost sales.
  • • Telephone Miscommunication: Phone orders frequently result in incorrect dish items, dietary mistakes, and incorrect delivery addresses.
  • • Static Paper Menus: Reprints are expensive whenever prices fluctuate or ingredients change, leaving customers with outdated menus.
  • • Opaque Calculations: Customers lack visibility into delivery fees, taxes, and applied coupon discounts prior to billing.

✅ FoodHub Digital Solution

  • • 24/7 Instant Access: Diners can view menus and order from anywhere on phone, tablet, or PC with zero wait time.
  • • Exact Digital Receipts: Every order contains transparent breakdowns: Subtotal + Delivery + 8% GST Tax = Total Bill.
  • • Real-Time Dish Management: Admins can update prices, toggle availability, or add seasonal specials in real time.
  • • Live Kitchen Dashboard: Automated order ticket queuing with sound alerts eliminates paper ticket clutter.
Slide 04

Project Objectives

Primary development goals and deliverables of the FoodHub system

01. Single Page Application (SPA)

Deliver instantaneous client-side page transitions and lightning-fast search without full page refreshes using React 18.

02. Role-Based Access Control

Strict separation of user personas: Customers browse and order, while Administrators manage the menu and fulfill kitchen tickets.

03. Dynamic Menu Catalog

Provide instant category filtering, pure vegetarian vs. non-veg toggles, and live price/rating sorting.

04. Transparent Checkout

Dynamic cart engine with subtotal computation, coupon discount support (`WELCOME30`), and GPS delivery address auto-detection.

05. Kitchen Display System (KDS)

Equip kitchen staff with a real-time order board, sound chimes for incoming tickets, and one-click status transitions.

06. Cloud Scalability

Deploy the application globally on Vercel with a resilient cloud database cluster hosted on MongoDB Atlas.

Technologies Used & Their Roles

Full-stack technology stack powering the FoodHub ecosystem

⚛️

Frontend

  • React 18: Component hierarchy, hooks (`useState`, `useEffect`, `useContext`).
  • Tailwind CSS: Utility-first styling & micro-animations.
  • Vite: Ultra-fast bundler with Hot Module Replacement.
  • React Router: Client-side navigation & route guarding.
🟢

Backend

  • Node.js: Asynchronous, event-driven JavaScript engine.
  • Express.js: RESTful API routes, JSON parsing & CORS handling.
  • Vercel Functions: Cloud serverless execution endpoints.
🍃

Database

  • MongoDB Atlas: Multi-region cloud NoSQL database.
  • BSON & ObjectId: Document mapping and relational refs.
  • MongoDB Native Driver: High-performance connection pooling.
🔐

Security & Tools

  • JWT: Signed token authorization.
  • Bcrypt.js: One-way salted password hashing.
  • VS Code: Code editing & debugging environment.
  • Git & GitHub: Version control & cloud repository.

System Architecture & Order Workflow

Three-tier architecture and end-to-end data pipeline

Three-Tier Architecture Diagram

Tier 1: Client Layer

React 18 Single Page App

Tailwind CSS • Context API • Lucide Icons

Tier 2: Business Logic Layer

Express.js / Vercel API

REST Routes • JWT Auth Middleware • CORS

Tier 3: Database Layer

MongoDB Atlas Cloud

Users • Foods • Orders Collections

Step 1: Selection Customer adds dishes to cart with itemized pricing and coupon validation.
Step 2: Submission Delivery details submitted via `POST /api/orders` with token authentication.
Step 3: Kitchen Sync Order saved to MongoDB Atlas; Admin board chimes & highlights the order card.
Step 4: Dispatch Staff transitions ticket (`Preparing` ➔ `On the way` ➔ `Delivered`).
Slide 08

Database Design (MongoDB Atlas)

NoSQL document schemas for Users, Foods, and Orders collections

Collection: `users`
_id: ObjectId (PK)
name: String
email: String (Unique)
password: String (Bcrypt)
role: "customer" | "admin"
phone: String
address: {street, city, zip}
createdAt: ISODate

Stores user profiles and cryptographic authentication hashes.

Collection: `foods`
_id: ObjectId (PK)
name: String
description: String
price: Number
category: String
image: String (URL)
isVegetarian: Boolean
isAvailable: Boolean
rating: Number

Dynamic dish catalog managed via Admin CRUD actions.

Collection: `orders`
_id: ObjectId (PK)
userId: ObjectId (Ref)
customerName: String
items: Array[{name, price, qty}]
deliveryAddress: Object
subtotal: Number
tax: Number (8%)
totalAmount: Number
orderStatus: "Placed"..."Delivered"

Records confirmed transactions and live fulfillment status.
